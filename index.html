Resumable file upload

Pick a large file and start the upload. Pause it, cut the connection, or even close the tab: the upload continues from where it stopped instead of starting over.

Request log

    
    
    
    
      
      
    
    
    POST creates the upload, PATCH sends a chunk, HEAD asks "how much do you have?" when the client resumes. Click a line to see its headers or copy it as a curl command.
  
    

  
    
    
    Interrupted uploads
    
    
    
    
    
      
    
    
    The browser remembers where each unfinished upload lives. After a reload, add the same file again (for a test file, use the same size and seed) and the upload continues from what the server has.
  
    

  
    
    
    Append mode
    
    
    
      
    
    
    
    
      
      
      
      
    
    
    
    
    Creates an upload without a length, adds lines to it, then fixes the length to finish it. This is the log-file case from the architecture decision (creation-defer-length).
  
    

  
    
    
    Fault injection
    
    
    
      
      
      
      
    
    
    
    
      
      
      
      
    
    
    No fault is active.
    The faults are added by serve.py between this page and the service. After a lost answer or a cut chunk, the uploader should ask "how much do you have?" (HEAD) and continue from there. (Browsers sometimes re-send a chunk by themselves after a dropped connection; the server then answers 409, which the uploader also has to recover from.) A speed limit gives you time to pause a fast upload.
  
    

  
    
    
    Test suite
    
    
    
      
      
      
    
    
    
    
    
      
    Creates small uploads at the endpoint above and checks the answers against the tus protocol and the extensions in the architecture decision: creating, resuming, wrong offsets, finishing, downloading, expiry, appending, checksums and termination. "Warn" means the service differs from a recommendation; "skip" means it does not advertise that extension yet. It sends real requests, so use a development environment.
